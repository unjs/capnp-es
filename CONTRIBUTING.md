# Contributing

## Local development

- Install the latest LTS version of [Node.js](https://nodejs.org/en/)
- Enable [Corepack](https://github.com/nodejs/corepack) using `corepack enable`
- Install the [Cap'n Proto tools](https://capnproto.org/install.html) (`capnp` must be on your `PATH`)
- Install dependencies using `pnpm install`
- Run interactive tests using `pnpm dev`
- Run all the checks using `pnpm test`

## Commit messages

The changelog is generated by [changelogen](https://github.com/unjs/changelogen) from [conventional commit](https://www.conventionalcommits.org/) messages (`fix: ...`, `feat: ...`, ...).

Commits that do not follow the convention are not listed in the changelog. As PRs are squash merged, make sure the PR title follows it.

## Release

Releases are done from an up-to-date and clean `main` branch:

```sh
git switch main
git pull --ff-only
pnpm release
```

`pnpm release`:

1. runs the checks (`pnpm test`)
2. bumps the version, updates `CHANGELOG.md`, commits and tags the release, and pushes the commit and the tag (`changelogen --release --push`)
3. opens the GitHub release page, or creates the GitHub release when a token is available
4. builds and publishes the package to npm (`npm publish`)

To create the GitHub release automatically, and link the contributors to their GitHub profiles, provide a token:

```sh
GITHUB_TOKEN=$(gh auth token) pnpm release
```

### Preview the changelog

Run `pnpm changelogen` to print the changelog of the next release without changing anything.

### Troubleshooting

- If `npm publish` fails, the commit and the tag are already pushed: fix the issue and run `npm publish` again.
- The changelog starts from the latest tag reachable from `main` (`git describe --tags --abbrev=0`). If that tag is not the previous release, run the steps manually with an explicit starting point:

  ```sh
  pnpm test
  pnpm changelogen --release --push --from <previous release commit>
  npm publish
  ```
